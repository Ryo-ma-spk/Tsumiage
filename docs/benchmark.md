# 似たサービスの分析と、積み上げの設計

場当たりに直すのをやめるための土台。
先に「他がどう解いているか」を見て、それから決める。

---

## 0. 日本語が翻訳調になっていた理由

指摘された文はどれも同じ壊れ方をしていた。

| いま | 何が変か |
|---|---|
| 2週間もつ見込み | 「もつ」＋「見込み」で名詞化しすぎ。誰も言わない |
| 覚えているつもりでしたが、確認したら違っていたところ | 見出しに**文**を置いている |
| この順で出てきます | 英語の説明文をそのまま訳した形 |

原因は語彙ではなく**構造**。
**英語のUIは文で説明し、日本語のUIは名詞でラベルする。**
私は英語の頭で文を書いて日本語に置き換えていたので、
中国語アプリのローカライズと同じ壊れ方をした。

直し方のルール：

- 見出し・ラベルは**名詞**にする。文にしない
- 「〜見込みです」「〜になります」を書きたくなったら、たいてい要らない
- 説明したくなったら、まず消す。消せないなら1行だけ

| 前 | 後 |
|---|---|
| 2週間もつ見込み | あと2週間 |
| 覚えているつもりでしたが、確認したら違っていたところ | 取りちがえ |
| この順で出てきます | 復習の順番 |
| いまのペースだと、受験日に覚えているのは72% | 受験日の見込み 72% |

## 1. 3つのサービスは何を返しているか

### Duolingo

- 数える単位は**1レッスン**。タップ1回ではない。
  ハードルを下げすぎると、続けても意味がなくなる
- 1日の目標は**本人が選ぶ**（5分〜20分相当）。
  高すぎる目標を勝手に設定すると、続くのではなく失敗が続く
- ストリークは損失回避で効く。ただし**凍結（freeze）を2回**用意する。
  許しすぎると習慣が壊れ、無いと1回の失敗で終わる
- いちばん落ちるのは**1日目→2日目**。設計の大半はそこを越えさせるためにある

### Studyplus

- 大学受験生の**2人に1人**が使う。解いている課題は「勉強が続かない」
- 教材ごとに勉強時間を記録して、**量を見えるようにする**
- **週間目標**を置く。しかも**達成するまで変更できない**
- 試験までのカウントダウン
- 友達をフォローして、いいねをもらう

### あすけん

- 毎日の記録に対して**その日の点数**が返る
- 栄養士キャラの「未来さん」が、褒めるだけでなく厳しく指摘もする
- 制限ではなく**見える化**で続かせる
- 体重の推移グラフ。**過去が線で見える**

### 共通しているもの

**3つとも「入れる」と「返ってくる」がはっきりしている。**

| | 入れるもの | 返ってくるもの |
|---|---|---|
| Duolingo | レッスン | XP・輪が埋まる・ストリーク |
| Studyplus | 勉強時間 | 積み上がる棒グラフ・週間目標の達成 |
| あすけん | 食事 | その日の点数・未来さんの一言・体重の線 |
| **Tsumiage** | **判定5枚** | **数字が少し動く** ← 弱い |

## 2. Tsumiage に欠けている3つ

### (1) 時間軸がない

**積み上げるアプリなのに、積み上がっていく様子が見えない。**

あすけんの体重グラフ、Studyplus の棒グラフ、Duolingo のカレンダー ——
どれも「時間 × 積み上げ」の線がある。Tsumiage にあるのは**今日の数字だけ**で、
先週の自分も、先月の自分もいない。

「1歩ずつ歩んでいる体感がない」のはこれが原因。
歩いた跡が残っていないので、歩いた気がしない。

### (2) 目標を本人が選んでいない

私は「今日ぶん 5つ」を勝手に決めて出していた。
Duolingo が本人に選ばせているのは、**勝手に決めた目標は失敗を量産するから**。

しかも日単位は脆い。1日休むと折れる。
Studyplus が**週**でやっているのは理にかなっている。

### (3) 残りの量が見えない

「まだこれだけ覚える必要がある」が、いまの画面にない。
全体の分母（55）を見出しから外したのは、**下位層に壁を見せないため**だったが、
外しすぎて**課題の大きさが分からなくなった**。

正しい答えは「隠す」ではなく「**手の届く時間軸で割る**」。
`あと23個` は壁だが、`今週あと8個` は歩ける。

## 3. 積み上げの設計案

### 3層にする

| 層 | 見せるもの | なぜ |
|---|---|---|
| **日** | 今日やった数（ノルマにしない） | 記録。折れないように、目標は置かない |
| **週** | 今週の目標と残り | ここが主役。1日休んでも折れない |
| **月／全体** | これまでの線と、残りの量 | 「歩いてきた」と「あとどれだけ」 |

### 週の目標は、本人が選ぶ

受験日から必要量を出したうえで、**ペースを3つから選ばせる**。

```
受験日まで 14週間 ／ まだ覚えていない 23 ＋ 復習に戻るぶん

  ゆっくり   週 6つ    受験日の見込み 78%
  ふつう     週 9つ    受験日の見込み 92%      ← おすすめ
  しっかり   週 14つ   受験日の見込み 99%
```

**選ばせるが、結果は正直に出す。** これは前提3（何をやるかは選ばせない）と矛盾しない。
選ぶのは「どれだけやるか」であって「何をやるか」ではない。

### 週は折れない

- 週の途中で1日休んでも、週の残りで取り返せる
- 週が終わったら締めて、次の週へ。**達成は取り消されない**
- ストリークは日ではなく**週**で数える（「7週つづけて達成」）

日のストリークは1日の失敗で全部消えるので、
「忘れてもコマは戻さない」という前提とぶつかる。週なら両立する。

### 過去が見えるようにする

```
      月  火  水  木  金  土  日
 今週  ■   ■   ・   ■   ■   □   □      5 / 9
 先週  ■   ■   ■   ・   ■   ■   ■      9 / 9  ✓
 先々週 ■   ・   ・   ■   ■   ■   ・     6 / 9
```

あすけんの記録カレンダーと同じ役割。
**歩いた跡が残る**ので、1歩ずつ進んでいる感じが出る。

そのうえで月ごとの数字を1行。

```
7月  +18       8月  +14 （いま）
```

## 4. 「何ができるアプリか分からない」への答え

いまの最初の画面は、数字とカードだけで、**このアプリが何をするのか言っていない**。

Duolingo は開いた瞬間に**道**が見える。あすけんは**その日の点数**が出る。
どちらも1画面で「何のアプリか」が分かる。

Tsumiage の一言は決まっている。

> **覚えたことが積み上がって、忘れる前に戻ってくる。**

これが最初の画面で伝わっていないなら、画面が間違っている。
初回だけ、3画面くらいで何をするアプリか見せる必要がある。

## 5. 決める順番（次はここから）

場当たりを止めるために、**この順でしか進めない**。

1. **週の目標をどう置くか決める**（本人が選ぶ／自動で決める／置かない）
2. **時間軸の見せ方を決める**（週カレンダー／月の折れ線／両方）
3. 決まってからモックを作る
4. モックが7基準（`docs/success-criteria.md`）を満たすか確認する
5. それからコードを触る

**1と2が決まるまで、実装しない。**
