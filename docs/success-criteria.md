# 成功指標と、理想の設計

デザインが何度も変わったのは、判断の基準が無かったから。
「よさそう / よくなさそう」でしか判定していないので、止まる条件がない。
ここを基準にする。

---

## 0. ゴール

> **進捗を可視化することで、より効率的な受験勉強ができること。**

効率とは「**同じ時間で、本番に残る量が多い**」こと。増やす手は3つしかない。

| 手 | 中身 | アプリの担当 |
|---|---|---|
| **1. 無駄を削る** | やらなくていい範囲をやらない | 志望校で範囲を絞る |
| **2. 落とさない** | 覚えたものを忘れたまま本番に行かない | 鮮度の予測と復習の順番 |
| **3. 迷わない** | 何をやるか決める時間をゼロにする | つぎの1つを出す |

**「たくさん勉強させる」は担当しない。** 量を増やすのは本人の時間の話で、
このアプリは同じ量から取り出せる成果を増やす側。

---

## 1. 成功指標

### いちばん上の指標

> **受験日に「覚えている」状態で迎えられた出題範囲の割合。**

これがすべて。ただし1人につき1回しか測れないので、日々の運転には使えない。

### 先行指標（使ってもらえたら測る）

| 指標 | なぜ見るか | 目安 |
|---|---|---|
| **7日後もまだ開いているか** | 使われなければ他の指標に意味がない。**最重要** | — |
| 1セッションの所要時間 | 通学中に収まるか。超えると習慣にならない | 60〜90秒 |
| 自己申告と確認カードの一致率 | 鏡が歪んでいないか。低いと数字が全部嘘になる | 85%以上 |
| 薄れる前に戻せた割合 | 「忘れる前に復習」が効いているか | 高いほど良い |
| 手つかずの観点が減る速さ | 網羅に向かっているか | — |
| 「今日ぶん」到達率 | 目標の置き方が現実的か。低すぎも高すぎもだめ | 60〜80% |

### 設計指標（ユーザーがいなくても、いま測れる）

**こちらが今日から使える基準。** モックを見て判定する。

| # | 基準 | 判定のしかた |
|---|---|---|
| A | 開いて**2秒**で「自分がどれだけ積んだか」が言えるか | 画面を2秒だけ見せて聞く |
| B | 画面でいちばん大きい要素が「積んだもの」か | 目視 |
| C | 次にやることが**1つ**に定まっているか | 選択肢の数を数える |
| D | 画面の言葉が**中学生の語彙**か | 造語・専門語を数える。0が目標 |
| E | 最初の1週間で「達成」が**3回以上**来るか | 単元の粒度から計算 |
| F | **下位層の初日**の画面が、不足ではなく達成を見せているか | 目視。★ いま落ちている |
| G | 1セッションが**90秒**に収まるか | 枚数 × 1枚あたりの秒数 |

## 2. 「様々な偏差値」が、いちばん重い制約

同じ画面を、**5%しか進んでいない子と、90%進んでいる子が両方見る。**

いまの設計はここで失敗している（基準F）。

```
上位の子が開く          下位の子が開く
32 / 55 個              3 / 55 個
■■■■■■■■■□□□□      ■□□□□□□□□□□□□
→ あと少し。埋めたい      → 52個も残ってる…
```

**同じ絵が、片方には燃料、もう片方には壁になる。**
網羅性とコンプリート欲は「もう少しで終わる人」を動かすが、
「まだ始めたばかりの人」からはやる気を奪う。

### 答え：分母を近くに置く

全体（55）は見られるようにするが、**見出しにはしない。**
見出しはいつも「**いま手の届く完成**」にする。

```
✗  3 / 55 個
✓  中1 正負の数    ●●     2 / 2  ✅ そろった！
   いま  中1 文字と式  ●○   1 / 2
```

- 単元は21個あり、1つは**2〜4観点**。数日で1つ終わる
- どの偏差値でも「次の完成」までの距離が同じくらいになる
- 全体は下にスクロールすれば見える。**閉じないが、頭に置かない**

これで基準E（1週間に3回の達成）と基準F（初日に達成が見える）が同時に立つ。

## 3. 理想の設計

### 一日の体験（これに収まっていれば良い設計）

```
 0秒  開く
 2秒  積んだ数が見える
 5秒  つぎの1つが名前で出ている  →  はじめる
45秒  5枚ふる
55秒  増えたぶんが絵で変わる     →  おわり
```

**55秒。** 通学中の電車で1駅ぶん。これを超える設計は却下する。

### 守る形

| # | かたち | なぜ |
|---|---|---|
| 1 | 画面あたりの**主役は1つ** | 2秒で読ませるため |
| 2 | 分母は**手の届く距離**に置く | 偏差値によらず動けるため |
| 3 | 数字より**絵**。数字を出すなら整数 | 小数は行動に変わらない |
| 4 | 出す言葉は**中学生の語彙だけ** | 造語は説明コストになる |
| 5 | 足りないときも、**責めずに差分**で言う | 目的は不安の解消 |
| 6 | 一度立った印は**外さない** | 取り消される達成は逆効果 |
| 7 | 迷ったら**消す** | 対象が広いほど、機能は少ないほうが通る |

### 3つの画面の役割（固定する）

| タブ | ひとことで | 主役 |
|---|---|---|
| **今日** | いま何をするか | つぎの1つ |
| **マップ** | どこまで来たか | いま埋めている単元 |
| **じぶん** | 全体はどうか | 積み上げ全体と、ずれの通知 |

**これ以上増やさない。** 迷ったら消す。

## 4. いま落ちている基準

| 基準 | 状態 |
|---|---|
| F 下位層の初日 | ✗ 3/55 と 52個の空きマスが出る。壁になっている |
| A 2秒でわかる | △ 積み上げが最上部に来て改善したが、55個の帯は2秒では読めない |
| E 1週間に3回の達成 | △ 単元コンプリートは作ったが、見出しに出ていない |
| D 中学生の語彙 | △ 「観点」がまだ画面に残っている |

**次に直すのはF。** ほかの基準は、Fを直すと自動的に上がる。
